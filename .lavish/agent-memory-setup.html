TL;DR — the verdict

You're already ~80% at best practice. Don't add infrastructure — close three small gaps.

Your setup (one instruction file both agents read via symlink + a checked-in docs/ knowledge base) is the pattern the ecosystem converged on. The industry name for what your docs/ already does is the "memory bank" pattern. The only real hole: Claude's private auto-memory is invisible to Codex, and nothing tells either agent where learned facts should land.

  • Add a memory-routing rule to CLAUDE.md — project learnings → docs/ (all agents see them); Claude-workflow-only prefs → auto-memory. One paragraph, fixes the silo permanently.
  • Create the missing docs/decisions.md — it's your shared long-term "what we decided & why" memory, referenced by CLAUDE.md but doesn't exist.
  • Optionally flip the symlink — make AGENTS.md the real file, CLAUDE.md the symlink. Future agents (Cursor, Gemini CLI, 25+ tools) then work with zero setup.
  • Skip MCP memory servers and vector DBs. Real tech, wrong scale for a solo dev — and files-in-git beats them on auditability anyway.

Finding 1 · The mental model

Everyone converged on the same three-layer split

Across Cline's Memory Bank, Cursor rules, AGENTS.md guides, and MCP memory write-ups, the same separation keeps reappearing — and it maps 1:1 onto files you already have.

01

Instructions

"How do we work here?"

Stable rules: build commands, conventions, architecture, guardrails. Checked in, versioned, rarely churns. This is what AGENTS.md / CLAUDE.md are for — and only this. Vika: CLAUDE.md.

02

Memory

"What have we learned & decided?"

Accumulates over time: decisions + rationale, discovered constraints, canonical numbers, design docs. Grows append-ish, needs an index. Vika: docs/ — plus the Claude-only auto-memory silo (the gap).

03

State

"What are we doing right now?"

Current focus, todos, blockers. Living snapshot, rewritten not appended, rots fast if unmaintained. Cline calls it activeContext.md; Vika calls it docs/state.md. Same thing.

Why the split matters for tokens: instructions load into every session prompt, so they must stay lean (one guide cites HumanLayer research that frontier models reliably follow only ~150–200 instructions single-source). Memory and state should be pulled on demand — an index the agent reads, then opens only the relevant file. That's exactly your "grounding" rule, and it's the right call.

Decision

Four options, ranked

#1

A · Route memory into the repo (minimal delta)

Recommended

Keep everything you have. Declare docs/ the shared memory for all agents and add one routing rule to CLAUDE.md: anything project-relevant an agent learns goes into the owning docs/ file; auto-memory is only for Claude-specific workflow preferences. Create the missing decisions.md. Because AGENTS.md is the same bytes, Codex inherits the exact same rule for free.

Pros

  • Zero new infra, zero dependencies
  • Memory is versioned, diffable, reviewable in git
  • Preserves your "one fact, one place" rule — no parallel store to drift
  • Any future agent that reads files (all of them) gets it free

Cons

  • Relies on discipline — agents must be told to write learnings down (the rule does that, but it's prompt-enforced, not mechanical)
  • Codex won't proactively self-journal the way Claude auto-memory does; it only writes when instructed by AGENTS.md
Effort: ~20 min · Risk: none · Reversible: trivially
#2

B · Flip the symlink: AGENTS.md becomes the real file

Do with A

Same content, swapped roles: AGENTS.md is the real file, CLAUDE.md → AGENTS.md. Claude Code follows the symlink identically, so nothing changes for it — but the 25+ tools that look for AGENTS.md by name (Cursor, Gemini CLI, Copilot, Windsurf…) now find a real file with zero setup the day you try one. Git tracks symlinks, so this survives clones.

Pros

  • Future-proof: standard-named file is the canonical one
  • 5-minute change, cosmetic risk only

Cons

  • Symlinks are awkward on Windows (needs Developer Mode) — irrelevant on your Mac, worth knowing if a collaborator ever clones on Windows multi-source
  • If Claude Code ever gains richer CLAUDE.md-only features (@imports, path-scoped rules), you'd want the real CLAUDE.md back — easy to re-flip
Effort: 5 min · Risk: cosmetic · Reversible: trivially
#3

C · MCP memory server (MemPalace / engram / Basic Memory)

Revisit later

Run one memory service both agents connect to over MCP. Genuinely the right architecture once you have teams of agents or humans who can't all read one repo — and the only family that gives semantic search over memories. Today it would violate two of your own rules: it's a new dependency (ask-first rule) and it moves facts out of the one-fact-one-place system into an unauditable store.

Pros

  • True automatic cross-tool memory, queryable
  • Scales past what files can index

Cons

  • Service to run/maintain (or a cloud account holding your project brain)
  • Memory leaves git — no diff, no review, no provenance
  • Duplicates docs/ → guaranteed drift against canonical-numbers.md
Trigger to revisit: 3+ agents in rotation, or memories outgrowing grep
#4

D · Symlink Claude's auto-memory dir into the repo

Rejected

The literal version of "make your memory file appear for other agents": link ~/.claude/projects/…/memory/ into the repo so Codex can read it. Rejected: the harness owns that directory's lifecycle and format; the path is machine-specific (breaks anywhere else); its content is written for Claude, not as shared docs; and you'd end up with two competing knowledge stores — the exact drift your one-fact-one-place rule exists to prevent. Option A gets the same outcome (Codex sees project learnings) the clean way: route the facts to docs/ instead of exposing the silo.

The concrete setup

What I'd actually change (A + B, four steps)

1

Add a memory-routing rule to CLAUDE.md Part 1

Slots in right after "Writing docs (one fact, one place)". Because AGENTS.md is the same file, Codex reads it too:

## Agent memory routing (all agents)
docs/ is the shared memory for every agent on this repo. Anything learned that outlives
the session and matters to the project — a decision, a constraint, a number, a gotcha —
goes in the owning docs/ file (decisions.md / canonical-numbers.md / state.md / reference/),
not in any tool-private memory. Tool-private memory (Claude auto-memory, Codex memories)
is for how-I-work preferences of that tool only, never project facts.
End of a work session that produced decisions or learnings: write them to docs/ before stopping.
2

Create docs/decisions.md (fixes the dead reference)

Seed it thin — an entry template plus backfill of the 2–3 decisions you already treat as settled (v4.3 plan shape, symlink approach, h265 re-encode). Append-only, mark superseded, never delete — the rules CLAUDE.md already states:

# Decisions — append-only ledger. Mark superseded, never delete.

## 2026-07-05 · docs/ is the cross-agent shared memory
Status: active
Decision: All agents route project learnings to docs/; tool-private memory
holds tool workflow prefs only. AGENTS.md stays a symlink twin of CLAUDE.md.
Why: One fact one place; git-versioned memory beats siloed/tool-private
stores for a solo dev. MCP memory servers deferred until 3+ agents.
Alternatives considered: MCP memory server (infra overkill),
exposing Claude auto-memory dir (machine-specific, format not shared).
3

Flip the symlink (optional, 5 min)

# AGENTS.md becomes the real file, CLAUDE.md the symlink
rm AGENTS.md
mv CLAUDE.md AGENTS.md
ln -s AGENTS.md CLAUDE.md
git add -A AGENTS.md CLAUDE.md

Claude Code behaves identically through the symlink; every AGENTS.md-native tool now works with zero setup. Re-flip any time if CLAUDE.md-only features become worth it.

4

Nothing to migrate from auto-memory today — and that's the point

Your auto-memory currently holds exactly one fact (the lavish-HTML delivery preference), and it's genuinely Claude-workflow-specific — it stays. Going forward the routing rule keeps it that way: project facts land in docs/ where Codex sees them, and auto-memory stays a thin layer of Claude quirks. Periodic check: if a memory file in there ever describes Vika rather than how Claude should behave, it's in the wrong place — move it to docs/.

What this buys you concretely: next time Codex works a session, it reads the same manual, the same decision ledger, the same numbers — and when it learns something (a build quirk, a threshold that works), the manual tells it to write that where Claude will find it next session. Two agents, one brain, no new moving parts.
