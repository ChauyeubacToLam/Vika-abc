03 · The centerpiece

The re-activation ritual — one full rest cycle

Timeline of one breather (High Plank, rest constant R = 5s, re-arm hold = the same 3s HOLD_STILL_REQUIRED_DURATION as set start):

  1. t = 0 · hold N completes (holding → resting) "Hai!" numeral voice FIFO + hold-end tone earcon ∥ — locked round-2 behaviour, unchanged. Amber RestCountdownRing crossfades in and drains (typed liveRestSeconds drives it, U2 as built). No rest-start voice (V1). AS BUILT: entering resting also clears the countdown trackers (_countdownSpoken + _holdCountingActive, policy_voice_coach.dart:509–512) so every breather earns a fresh "ba, hai, một".
  2. t = 0 → R · the breather (STRICTLY timed, as built) Silence. Ring drains, numeral counts down. The rest state is pose-INDEPENDENT — its only exit is the 5s elapsing (high_plank.dart:547–551) — so the rest countdown is honest by construction. No predictive spoken countdown (confirmed).
  3. t = R · rest timer completes (resting → reArming, the timed edge) Rest-end tone earcon ∥ fires deterministically on the enteredReArming edge (EarconPlayer.restEndTone(), policy_voice_coach.dart:513–515; asset assets/audio/common/rest_end_tone.mp3). Ring is drained; its centre flips to "Vào tư thế" — as built, RestCountdownRing grew a centerLabel that the page sets while re-arming (active_exercise_page.dart:2207–2212). No instruction voice — the ring IS the instruction channel (v4). A user already back in the pose flows straight into the countdown (the 4-frame pose debounce simply confirms immediately).
  4. t = R → pose · reArming, pose not yet confirmed Screen shows "Vào tư thế"; no coaching/instruction voice (v4) — no re-tell. AS BUILT clarification: safety guidance CAN still speak here, ungraced (out-of-frame, orientation, etc. — "voice-silent" never meant deaf safety); a stuck-but-present, in-frame user hears nothing by accepted-risk ruling — device watch item (§04-C). Pose confirm = the existing 4-frame outer-pose debounce (high_plank.dart:88, :552–556); pose loss, bad pose, orientation loss, or missing landmarks resets the re-arm clock.
  5. pose confirmed · re-arm hold starts The 3s activation-hold clock runs again (_reArmHoldStartMs, surfaced through the overridden holdStillElapsedMs/activationProgress). UI: the SAME yellow activation gauge (remaining-seconds numeral, "Sẵn sàng" at ready) via the widened _overlayState. Voice: the SAME _handleActivationCountdown speaks "ba" (800ms) → "hai" (1600ms) → "một" (2400ms) voice FIFO via the widened inActivationContext — the first coaching voice since the hold-count numeral at rest start. A pose break nulls the clock, drops pending counts, and re-arms from "ba" (existing perishability, verified).
  6. re-arm hold lands (3s) · reArming → holding commit Hold N+1's clock starts — only now: the commit runs timerMetric.resetForNextHold() for a fresh hold (high_plank.dart:577–583; a mid-hold drop still pause-resumes — only setup/rest begin fresh). The reminder ("Lần này bạn nhớ…"), if earned by a fault in hold N, fires at this commit edge — its locked ruling verbatim — and queues right behind "một" voice FIFO (§04-A). Work ring crossfades back in.
  7. t = T/2, T−10, T−5…T−1, T · inside hold N+1 Milestones, spoken final countdown, hold-end tone — all locked round-2 behaviour, untouched. First possible milestone (halfway) sits ≥7s after the reminder on a 15s+ hold — no congestion.
The design principle that makes it clean The ritual is a re-arm, not a copy. Both set-start halves are clock-followers: voice follows holdStillElapsedMs, UI follows activationProgress. The re-entry exposes the SAME clock surfaces during a new re-arm phase, and both followers light up with their trained behaviour — offsets, perishability, gauge visuals — with no parallel implementation (the intro-termination rule stays set-start-only; nothing plays at re-arm for a count to cut). Zero new grammar for the user (Nam's why: "just like how they got in at the beginning"), near-zero new machinery for the code — and under v4, what re-arms is the clock-follower ONLY, never the grace anchors around it (§04-D).
Cost flag for device (feel-tune, not a blocker) The ritual stretches the effective inter-hold gap: R (5s) + pose re-entry time + 3s re-arm ≈ 8s+ between holds vs plank's flat 5s today (v4 trimmed the estimate's upper end — no instruction line plays, so the only variable is how fast the user re-poses). Physiologically fine (it is still a breather), but the McGill-style short-rest intent behind plank's 5s constant gets diluted. If device feel says the cycle drags, the knob is REST_DURATION per exercise (e.g. 3s), NOT thinning the ritual — the ritual is the ruled invariant.

04 · Reconciliations

The five overlaps, made clean

A · Where the reminder sits in the ritual

The locked commit edge ("hold N+1's re-entry into holding") survives the ritual unchanged — re-entry into holding now happens when the re-arm hold lands, so the reminder fires there and FIFO-queues behind "một", landing in the hold's first ~1–2s. Under v4 this is also the ONLY possible voice slot in the ritual (the re-arm is voice-silent), and it is the right one anyway: feedforward research (§3b) wants the cue adjacent to the action it fixes, and the commit edge is the action starting. Collision math: "một" is ~0.4s, the reminder ~1.5s, the first milestone ≥7s away on any hold long enough to have one. Clean — and the reminder is now the only line that can play between the rest-end tone and the next milestone.

B · Rest-end tone asset — RESOLVED: sibling landed

Nam confirmed the sibling pick; the asset EXISTS: assets/audio/common/rest_end_tone.mp3 (candidate_192761, 1.0s bell ding, CC0 freesound.org/s/192761). The reasoning that drove it, kept for the record: two identical bells ~5s apart would make one sound mean two opposite states — "you're done, rest" and "rest's done, work" — un-training the round-2 rule that sounds carry state. Registers now differ the way the states do: hold-end = the boxing bell's "time!" release (157277, 2.7s ring-out); rest-end = a short bright ding that reads "bell for round 2" (and under v4 it stands alone — no line follows it). It is an EarconPlayer sound like the end tone (direct path, never in commonFiles); Codex adds no files.

C · Stuck user — RE-RULED v4: no voice backstop at all

The rest-end tone + the persistent "Vào tư thế" ring ARE the nudge — and the ONLY nudge. The v3 instruction line and its ~10s voice re-tell are both dead (Nam: the set intro already taught the pose; zero coaching voice between tone and countdown). A stuck-but-present user sees the ring indefinitely and hears nothing — accepted risk, device watch item: this is the one place the design tolerates a silent screen-dependent state for a floor-bound user, by explicit ruling. AS BUILT clarification (accepted): "voice-silent" scopes to instruction/coaching voice only — SAFETY guidance still speaks during re-arm, ungraced (a user who drifts out of frame or loses orientation mid-rest gets the normal guidance line; the implementation resolved the spec's wording tension in favor of safety). The presence gate still owns walk-away; quit still owns give-up. No new keys (common.rest_over and common.hold_reengage both dead).

Shared-key note (v4 — mostly dissolved): <slug>.setup_position keeps exactly its two existing notActivated moments — the set-start intro broadcast and the set-start stuck-user re-tell. Nothing in the ritual fires it. The v3 four-moment coexistence design is superseded; the only residual instruction to Codex is negative: do not wire any setup_position (or other) voice into the re-arm phase, and verify the GuidanceClass.setupPosition producer stays quiet while activated (it should already — it is a pre-activation mechanism).

D · The state-machine gate (same machinery, not a parallel copy) — and NO grace import

The resting → holding transition becomes a two-stage gate: stage 1 (timed) — restElapsed >= REST_DURATION flips resting into a re-arm phase (this timed flip is the tone + U3 edge); stage 2 (ritual) — in re-arm, the exercise runs the SAME pose-confirm + 3s hold-clock pattern as base activation and only commits to holding when the clock lands. AS BUILT exactly this shape: HighPlankState.reArming is a real state; High Plank overrides isReArmingHold + the two clock getters (high_plank.dart:124–140 — Codex resolved the PUSH BACK toward widened getters, not parallel ones); the adapter gate is inActivationContext = notActivated || isReArmingHold (policy_voice_coach.dart:439–442) and the UI's _overlayState resolves re-arm-with-progress to hold (active_exercise_page.dart:2472–2476). Base state stays activated throughout — the setup intro, guidance latches, and set-level one-shots correctly do NOT re-fire; only the countdown re-arms per hold, BY DESIGN. AS BUILT hardening (Codex, test-proven): the intro-termination branch gained a structural exerciseState == notActivated guard (:456–459) — a test showed _introAudioEnded CAN still be false at the first re-arm, and without the guard a re-arm count would have killed intro grace bookkeeping. Set-start behaviour unchanged.

NO guidance grace during re-arm (explicit v4 ruling) — VERIFIED IN CODE: the grace re-pin is explicitly excluded from rest and re-arm (policy_voice_coach.dart:236–240: the pin condition carries currentPhaseKey != 'resting' && !exercise.isReArmingHold), so guidance signals (body_in_frame, turnSide, etc.) run UNGRACED through rest and re-arm, exactly as during holds. Set-START grace behaviour is unchanged — and the intro-termination guard above is part of the same protection (a re-arm count can no longer close intro grace on set-start's behalf).

E · U3 + V2 are one designed moment (screen + audio twins)

One moment, two renderers, one truth — the GuidanceSignal pattern. At the timed edge the state flips to re-arm, and BOTH channels render that flip: audio = the rest-end tone, alone (v4 — sounds carry state; words stay out of the rest); screen = the drained ring's centre swaps its "0" for "Vào tư thế" (setup-style label, VikaIvory amber, matching the ring) — the visual is the ONLY instruction channel at this edge. When the pose confirms, the screen hands off to the activation gauge (remaining-seconds → "Sẵn sàng"), audio to "ba, hai, một" — both reading the same clock. Copy (final): screen "Vào tư thế" stands as ruled (U3); there is no voice copy — nothing to record or confirm. AS BUILT: RestCountdownRing gained a centerLabel parameter (the page passes it while re-arming, active_exercise_page.dart:2207–2212); once the re-arm clock runs (reArmProgress != null) the centre slot yields to the gauge (:2188–2191 exclusion + the widened _overlayState).

Ruled: former hold-based homework exercises become HYBRID — the time/hold rings AND the rep-tracking UI render together ("hybrid also needs to keep track of the reps — the same UI of checking reps needs to be there as well"). Today the two surfaces are mutually exclusive on one boolean:

  • Small OPEN (flag, don't block): the pre-exercise spec label (targetLabel: isHold ? 'GIÂY/HIỆP' : 'REP/HIỆP', exercise_experience_screen.dart:1174) has no hybrid form ("3 lần × 30 giây"-style). Cosmetic; the addendum spec flags it for a copy decision at implementation.

07 · Risks

Lines most likely wrong + what to stress-test

  • Ritual pacing (softened by v4). Tone → pose → 3s countdown, every hold, ~N times a set. The v3 concern (a long intro-register line looping every breather) is MOOT — no line plays. What's left to feel-check is only whether tone + 3s countdown per hold reads as structure or as ceremony on short holds; if it drags, the knob is REST_DURATION (§03 cost flag); do not cut ritual stages.
  • The gate-widening landed with a test-proven hardening (was the top code risk). The widened contexts are in (inActivationContext, widened _overlayState), and Codex's test caught the exact set-start perturbation this bullet feared: _introAudioEnded can still be false at the first re-arm, so the intro-termination branch now carries a structural notActivated guard (§04-D). Residual: device-confirm set-start feels identical (stress-test 6).
  • The silent stuck state is the accepted-risk watch item (unchanged by the build). A present-but-not-re-posing, in-frame user gets a persistent ring and zero audio — the one deliberate exception to the "floor-bound users can't read the screen" doctrine (safety guidance still covers out-of-frame/orientation, as built). Watch on device: if real users stall in rest confused, the revisit is a ruling change, not a quiet fix.
  • Grace carry-over — VERIFIED excluded in code (§04-D), device check remains. The grace pin explicitly skips resting/re-arm (policy_voice_coach.dart:236–240). The regression signature to watch on device stays: a guidance signal at a rest edge that waits ~3.5s instead of firing on its normal latch timing.
  • Reminder adjacency: "một" + reminder back-to-back at hold start is by design (count + outcome co-occur at rep boundaries all over the fleet), but this particular pairing is new — listen-check that it doesn't feel front-loaded on a 15s hold.
  • Hybrid layout on small phones: centre rings + bottom rep hero + phase chevrons render together for the first time; the existing collision comment (:1863 — the rep hero yields when signage collides) suggests the slots negotiate already, but portrait small-screen needs an eyeball pass.

Device stress-tests: (1) full 3-hold set — the ritual loops cleanly, countdown re-arms from "ba" after a deliberate mid-re-arm pose break; (2) stay planked through the rest — tone fires, countdown starts immediately, zero other voice; (3) never re-pose, staying in frame — verified NO coaching/instruction voice after the tone while the ring shows "Vào tư thế" indefinitely (the accepted-risk state — also gauge how it feels), then drift out of frame — the safety guidance line MUST fire, ungraced (the as-built safety exception); (4) faulted hold N — reminder lands right after "một" at hold N+1, never during the rest; (5) hybrid — rings AND rep hero both visible portrait + landscape, hero ticks per completed hold; (6) set-start unchanged — the widened gates didn't alter first-activation behaviour (intro termination, grace close, ready line); (7) grace check — break body_in_frame during a rest/re-arm: the guidance line must fire on its normal ungraced latch timing, not wait out any ~3.5s window.
