ELI5

Think of a real trainer. Your eyes (the metrics) notice "hips dropped too fast." Your judgment (the policy) decides whether it's worth saying anything right now, or whether you just said something and should let them breathe. Your mouth (the sink/player) actually makes the sound. This code keeps those three jobs in three different files so each can be reasoned about — and tuned — on its own.

02 The per-frame contract

One call, every frame — the adapter pattern

The camera pipeline was never modified for voice. It already called ExerciseVoiceCoach.processFrame(...) once per frame; the whole redesign slots in behind that unchanged interface. That's design decision D1: the adapter holds prior-frame state and diffs it, so the per-frame contract never had to grow richer.

ELI5 — what "diffing" buys us

The page doesn't say "rep 4 just landed with a neck fault." It just says "here's the current state, again." The adapter remembers what last frame looked like and works out the events itself: rep count went 3→4, this fault is new vs. still-present, the hold clock crossed 1600ms. Because the adapter owns that memory, the pipeline stays dumb and every other exercise keeps working untouched.

Glute Bridge is still the full-superset pilot: it owns soft pools, reminders, hustle phase keys and local tuning. The 24 Tier-1 rep exercises now return the same policy adapter with the smaller default contract: explicit rep bundle, target, normalized fault ids and three-field RepLog metadata. Hold exercises retain their existing paths. Tricep Dip gets structural voice but no live fault surface because its declared metrics are not driven by its exercise loop; pretending otherwise would violate data honesty. The per-exercise decision surface is in voice-fleet-tier1-review.html.

CueType — the nine kinds of thing Vika can say

enum CueType {
  /// The rep/hold counter ("Một", "Hai", ...). Not an "outcome" cue — it
  /// may co-occur with a [praise] or [criticalFault] cue on the same rep.
  count,

  /// Clean-rep acknowledgement ("Tốt lắm!"). Variable-ratio, never twice
  /// in a row, at most one outcome cue per rep.
  praise,

  /// A critical form fault (a fault whose `affectsForm` is true) — the
  /// real-time "fires immediately" cue. First occurrence in a rep is
  /// certain; persistence escalates. This IS what the behaviour spec calls
  /// "safety fires immediately": there is no separate injury cue, the
  /// critical fault is it.
  criticalFault,

  /// A non-critical measured fault (`affectsForm` false). Warmer than
  /// [criticalFault], still honest: the rep is not praised as clean, but the
  /// user gets a light nudge. Hunger + base probability, never
  /// first-occurrence-deterministic.
  softFault,

  /// Short feedforward line at the next rep-start edge after a live critical
  /// fault was seen in the previous rep. Outcome-class; same fault key as the
  /// correction path so it cannot double-speak inside that next rep.
  reminder,

  /// Deterministic structure copy: setup intro, ready, rest, set-complete.
  /// Always eligible to speak; the adapter latches each moment so it fires
  /// exactly once (behaviour spec hard-rule #2).
  setup,

  /// Sparse effort push. Arms on a stretched inter-rep gap, fires only at
  /// entry into the exercise's declared effort phase, and may pair with the
  /// one-remaining count anchor when the target proves it. Never mid-gap, and
  /// no per-set cap.
  hustle,

  /// Movement/phase cue (e.g. squat's "Xuống" / "Giữ" / "Đứng lên").
  /// Perishable — dropped rather than queued if the sink is already busy.
  phase,

  /// Life/safety line. Always speaks, bypasses hunger, highest priority.
  safety,
}

The split that matters most: outcome cues (praise, criticalFault, softFault, reminder, hustle) compete for at most ~2 slots per rep and respect the collision gap; count is not an outcome cue, so it can co-occur with any of them; setup and safety are deterministic structure/latch channels that bypass the outcome accounting entirely. Keep that taxonomy in your head — it's the spine of the policy in §04.

Why this is the right cut

faultPersistence and contentKey are the two fields doing the heavy lifting. Persistence is "how many reps in a row has THIS fault been present" — it drives correction escalation. contentKey is the hunger key, so staying quiet about the neck fault never raises the odds of the knee fault speaking. Both are adapter-computed (the policy is told, never tracks), which is exactly why the policy can be unit-tested with a hand-built context and no exercise at all.

ELI5

A VoiceScript is a recipe card for one exercise: "I'm glute_bridge, my faults are these five ids, here are my soft-nudge lines and my reminder lines, and a new rep 'commits' when I enter the ascending phase." The engine reads the card; it never hard-codes anything about the exercise.

04 Layer 2 · the brain

voice_policy.dart — whether to speak

This is the file to review hardest. It is pure and deterministic given its injected Random and clock — no I/O, no exercise knowledge. Everything about "sounds like a human, not a metronome" is built here: hunger keeps an average cadence without a learnable rhythm, hard rules stop back-to-back chatter, relief valves stop the coach ever going fully silent.

The rule shapes and their numbers

enum CueMode {
  /// Never rolls a die: safety always speaks, bypassing hunger entirely.
  always,

  /// Base probability that climbs with hunger (silence), plus its own hard
  /// rules (never twice in a row; at most one outcome cue per rep). Used by
  /// [CueType.praise].

class CueTuning {
  const CueTuning(
    this.mode, {
    this.base = 0.0,
    this.step = 0.0,
    this.cap = 1.0,
    this.reliefAfter = _noRelief,
    this.firstOccurrenceCertain = false,
    this.scalePraiseByFormScore = true,
    this.postFireIdlePenalty = 0,
  });

  /// Sentinel meaning "no relief valve for this type" — a persistence/idle
  /// value this large is never reached in practice.
  static const int _noRelief = 1 << 30;

  final CueMode mode;

  /// Probability when hunger/persistence is zero.
  final double base;

  /// Added per unit of hunger (silence), or — for [CueType.criticalFault] only —
  /// per unit of `ctx.faultPersistence`.
  final double step;

  /// Ceiling applied AFTER personality scaling.
  final double cap;

  /// Relief valve: once the cue's silence streak reaches this, it fires
  /// near-certainly instead of rolling. The streak source differs by type:
  /// [CueType.criticalFault] and [CueType.reminder] read
  /// `ctx.faultPersistence` (adapter-computed), [CueType.count] reads the
  /// policy-internal idle counter. Left at
  /// [_noRelief] for every other type, which has no relief valve.
  ///
  /// Sizing rule (Nam, 2026-07-08): a relief valve is a saturation guard,
  /// not a scheduler. Size it at the degenerate edge (the thing it exists
  /// to prevent — e.g. a whole set going by uncounted), never tight enough
  /// to bind on a typical set: a floor that binds every set is a metronome.
  final int reliefAfter;

  /// Opt-in correction hard rule: a fault's first appearance in a streak
  /// speaks with certainty. Default stays false so non-pilot exercises keep
  /// the current base-roll behaviour.
  final bool firstOccurrenceCertain;

  /// Legacy D8 praise scaling. Kept on by default to avoid changing other
  /// exercises while Glute Bridge removes the multiplier locally.
  final bool scalePraiseByFormScore;

  /// Optional stochastic backoff after a cue speaks. A value of 2 starts the
  /// next eligible roll two hunger steps below baseline, then normal silent
  /// attempts climb it back. This is deliberately not a fixed cooldown.
  final int postFireIdlePenalty;
}

Note postFireIdlePenalty (line 96-98): a value of 2 starts the next eligible roll two hunger steps below baseline — the deliberately-not-a-fixed-cooldown backoff hustle uses. And reliefAfter is the saturation guard: sized at the degenerate edge, never tight enough to bind on a typical set (a floor that binds every set IS a metronome).

The hunger formula — the heart of it

359 360 361 362 363
  /// scale: `(base + step·idle) · personality`, clamped by `cap`. The
  /// heart of "hunger" — shared by every mode that rolls a die. `idle` may be
  /// negative for post-fire stochastic backoff.
  double _p(CueTuning t, int idle) =>
      _clampD((t.base + t.step * idle) * personality, 0.0, t.cap);

ELI5 — hunger

Each cue type has an "idle" counter: how many times in a row it could have fired but the dice said no. Every silent turn nudges the probability up (step·idle), so the coach can't go weirdly quiet forever — but because it's still a dice roll, there's no countable "every N reps" rhythm. Fire, and the counter resets to 0 (or to a negative number if there's a post-fire penalty). Personality (0.5 quiet … 1.5 chatty, ships at 1.0) multiplies base+hunger but never the cap or a hard rule.

    final speak = _shouldSpeak(type, ctx);

  /// scoped to the specific fault/metric (`ctx.contentKey`) so staying silent
  /// about one fault never raises the odds for another; every other type
  /// collapses to a single per-set counter.
  String _key(CueType type, CueContext ctx) {
    return (type == CueType.criticalFault ||
            type == CueType.softFault ||
            type == CueType.reminder ||
            type == CueType.setup)
        ? '${type.name}:${ctx.contentKey}'
        : type.name;
  }

  void _onSpoke(CueType type, CueContext ctx, String key) {
    final postFireIdlePenalty = tuning[type]?.postFireIdlePenalty ?? 0;

    if (type == CueType.praise) _lastPraiseRep = ctx.repNumber;
    if (_isOutcomeCue(type)) {
      _recordOutcome(type, ctx);

The four gates, in order

1. _outcomeAudioPending — a previous outcome's audio is still playing → no. 2. nowMs < lastEnd + gap — within 0.5s of the last line's audio end → no (measured from end, so long lines can't chain). 3. if nothing has spoken this rep yet → yes. 4. otherwise this is a second cue this rep: allowed only if it's a criticalFault, under the cap-of-2, and a different fault than one already voiced. That's "per-MOMENT exclusivity": one outcome per moment, a second critical only later in the rep for a different fault.

        ctx.formScore >= _praiseBigFormScoreThreshold &&
        VoiceLib.praiseBig.isNotEmpty &&
        _rng.nextDouble() < _praiseBigBias) {
      pool = VoiceLib.praiseBig;
    }

    if (pool.length == 1) return pool.first;

    var candidates = pool;
    if (last != null) {
      final withoutLast = pool.where((k) => k != last).toList();

    final pick = candidates[_rng.nextInt(candidates.length)];
    _lastPickByPool[poolId] = pick;
    return pick;

ELI5 — "D8"

On a standout rep (formScore ≥ 0.85) the coach flips a coin (50%) to reach for a "bigger" praise line ("Tuyệt vời!") instead of a small "Tốt." Then, whatever pool it lands in, it avoids repeating the exact line it used last time from that same pool. That's all — small touches so praise doesn't sound canned. Glute bridge's formScore is binary (1.0 or 0.0), so in practice D8 fires the big pool on any clean rep.

The three edges to keep straight

justActivated (held the pose 3s) fires ready and, on a fresh set, the whole reset. justReactivatedAfterPause is a resume that re-enters the hold — it re-arms the countdown but does NOT replay the intro or wipe rep logs. restartedSet (machine dropped back to notActivated from a later state) re-arms the per-set one-shots for set 2+ — inert in the single-set pilot. Getting these apart is why the resume-vs-new-set behaviour is correct.

The intro + the voice-grace window

The per-set intro is an unconditional one-shot broadcast (it's what tells the user to get in frame, so it can't wait for in-frame). ELI5 — why grace = the intro's own length

The intro already says "get in frame and into position." If the safety channel also shouted "body in frame!" over that same audio, the user hears two voices talking over each other. So while the intro plays, in-position-fixable safety lines are muted (graced). The moment the intro finishes, grace closes and the safety line is allowed — it becomes the escalation, not a duplicate. If the intro produced no audio at all, a fixed ~3.5s fallback window stands in.

  void _handleActivationCountdown(ExerciseBase exercise) {

    final holding =
        holdMs != null && exercise.exerciseState == ExerciseState.notActivated;

    if (holding) {

      for (var i = 0; i < kActivationCountOffsetsMs.length; i++) {

          // A count firing while the intro is still playing TERMINATES it
          // (ruled): a user already holding the start position has no use for
          // setup instructions, and a count queued behind the intro would lag
          // the hold and read broken. Stop the sink (current + queued lines
          // dropped — the intro is one-shot and consumed, it never resumes),
          // mark intro-audio-end NOW so the voice grace closes with it and the
          // re-tell floor is stamped this same frame, then speak the count.

            _introAudioEndMs = exercise.frameTimestampMs;
            exercise.endGuidanceSignalGrace(nowMs: exercise.frameTimestampMs);

              'position) — grace closed',

          _coach.say(
            CueType.setup,
            VoiceContent.key('${i + 1}'),
            CueContext(repNumber: 0, contentKey: 'count_${i + 1}'),
          );
        }
      }
      return;
    }

    if (!_holdCountingActive) return;
    // The hold ended. A break (still notActivated) drops the perishable pending
    // counts so no stale count plays; activation (now activated) keeps the
    // queue so a mid-play "ba" survives. Either way the tracker re-arms.
    if (exercise.exerciseState == ExerciseState.notActivated) {
      _coach.clearPending();
      debugPrint(
        '[VoiceSetup] hold BROKE — pending counts dropped, countdown '
        're-armed from một',
      );
    }
    _holdCountingActive = false;
    _countdownSpoken.clear();

class _SteadyGuidanceLatch {
  _SteadyGuidanceLatch({
    required int enterFrames,
    required int exitFrames,
    required this.recueMs,
    this.fireOnEntry = true,
  })  : _enter = Debouncer(requiredFrames: enterFrames),
        _exit = Debouncer(requiredFrames: exitFrames);

  final Debouncer _enter;
  final Debouncer _exit;
  final int recueMs;

  /// When true (orientation / body_in_frame): fire on debounced entry, then ONE
  /// mid-set re-cue after [recueMs] of continuous latching. When false
  /// (stuck-setup): entry fire suppressed; the ONE fire IS the delayed re-tell.
  final bool fireOnEntry;

  bool _latched = false;
  bool _recued = false;
  int? _latchedSinceMs;

  _SafetyVoiceRequest? update({
    required bool present,
    required int nowMs,
    required _SafetyVoiceClass voiceClass,
    required String key,
    required bool graceActive,
    int? delayFloorMs,
  }) {
    if (graceActive) {
      _enter.update(present);
      if (!present) {
        _exit.update(true);
      } else {
        _exit.reset();
      }
      return null;
    }

    if (!_latched) {
      if (_enter.update(present)) {
        _latched = true;
        _recued = false;
        _latchedSinceMs = nowMs;
        _exit.reset();
        return fireOnEntry
            ? _SafetyVoiceRequest(voiceClass: voiceClass, key: key)
            : null; // suppressed entry fire — the delayed re-tell is the fire.
      }
      return null;
    }

    if (!present) {
      if (_exit.update(true)) {
        reset();
      }
      return null;
    }

    _exit.reset();
    final latchedSince = _latchedSinceMs;
    if (_recued || latchedSince == null) return null;
    // The single delayed fire references the LATER of (latch start, delay
    // floor). For the mid-set re-cue there is no floor → latch start. For the
    // stuck-setup re-tell the floor is intro-audio-end, so the re-tell is never
    // earlier than recueMs past the intro finishing, and a null floor (intro
    // still playing) blocks it outright — it never speaks over the intro.
    final int referenceMs;
    if (fireOnEntry) {
      referenceMs = latchedSince;
    } else {
      if (delayFloorMs == null) return null;
      referenceMs = latchedSince > delayFloorMs ? latchedSince : delayFloorMs;
    }
    if (nowMs - referenceMs >= recueMs) {
      _recued = true;
      return _SafetyVoiceRequest(
        voiceClass: voiceClass,
        key: key,
        trigger: fireOnEntry ? 'recue' : 'retell',
      );
    }
    return null;
  }

  void reset() {
    _latched = false;
    _recued = false;
    _latchedSinceMs = null;
    _enter.reset();
    _exit.reset();
  }
}

ELI5 — one latch's life

A condition (say "body not fully in frame") has to persist through a ~1s enter-debounce before the latch fires once. Then it stays silent while the condition holds. If the condition clears, it has to stay clear through a ~1s exit-debounce before the latch re-arms — that exit-debounce is the anti-ping-pong knob, so a flickering landmark can't machine-gun. If the same condition is still latched ~10s later, it speaks exactly one "fuller" re-cue, then goes quiet for real. During grace, the debouncers keep counting but nothing fires.

    final double baseline = _baselineHipY!;
    final double bottomTolerance = scaleFactor > 0
        ? scaleFactor * GluteBridgeConfig.BOTTOM_TOLERANCE_RATIO
        : GluteBridgeConfig.BOTTOM_TOLERANCE_PIXELS;

    final bool isAscending =
        hipVelocity < GluteBridgeConfig.ASCENDING_VELOCITY_THRESHOLD;
    final bool isDescending =
        hipVelocity > GluteBridgeConfig.DESCENDING_VELOCITY_THRESHOLD;
    final bool isAtRest =
        hipVelocity.abs() < GluteBridgeConfig.REST_VELOCITY_THRESHOLD;
    final bool isElevated = hipY < (baseline - hipElevatedThreshold);
    final bool isAtBottom = hipY >= (baseline - bottomTolerance);

    switch (gluteState) {
      case GluteBridgeState.bottom:
        if (_ascendDebouncer.update(isAscending)) {
          _peakHipY = hipY;
          _transitionState(GluteBridgeState.ascending, timestampMs);
        }
        break;

      case GluteBridgeState.ascending:
        // Normal path: reach top.
        if (_topHoldDebouncer.update(isAtRest && isElevated)) {
          _transitionState(GluteBridgeState.topHold, timestampMs);
        }
        // Fast-path: start descending immediately without holding.
        else if (_descendDebouncer.update(isDescending && isElevated)) {
          _transitionState(GluteBridgeState.descending, timestampMs);
        }
        // Abort: hip never got high enough and stopped moving.
        else if (_bottomDebouncer.update(isAtRest && isAtBottom)) {
          _transitionState(GluteBridgeState.bottom, timestampMs);
        }
        break;

      case GluteBridgeState.topHold:
        if (_descendDebouncer.update(isDescending)) {
          _transitionState(GluteBridgeState.descending, timestampMs);
        }
        break;

      case GluteBridgeState.descending:
        // Rep counted here when returning to bottom.
        if (_bottomDebouncer.update(isAtRest && isAtBottom)) {
          _onRepCompleted(timestampMs);
          _transitionState(GluteBridgeState.bottom, timestampMs);
        }
        // Fallback: If user goes right back into another rep without stopping at bottom.
        else if (_ascendDebouncer.update(isAscending)) {
          _onRepCompleted(timestampMs);
          _transitionState(GluteBridgeState.ascending, timestampMs);
        }
        break;
    }
  }

    if (_eccentricDuration == null || _concentricDuration == null) return;
    if (_concentricDuration! < 0.1) return; // avoid division noise

    _debugData['eccConRatio'] = ratio.toStringAsFixed(2);

    if (ratio < SpeedControlConfig.MIN_ECCENTRIC_RATIO &&
        !_velocityFaultAdded) {
