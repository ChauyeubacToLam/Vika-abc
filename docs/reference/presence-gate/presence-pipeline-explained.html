00 Orientation

The big picture — read this first

What these three files are, in one breath, and why they're separate.

🧒 Like you're five

Imagine a bouncer at a gym door. One person (the eyes) just stares at the doorway and says a number: "about 40% of what I see is a human body." That's PersonDetector. A second person (the judge) watches that number over time and makes calls: "they've stood there half a second — okay, confirmed, they're really here" or "they walked off 9-tenths of a second ago — pause the workout." That's PresenceGate. The third person (the conductor) runs the whole class — counts reps, checks form — and just asks the judge once per moment: "should I keep going or hold?" That's ExerciseBase. The eyes never make decisions; the judge never counts reps. Each has one job.

Until last week all of the judge's logic lived inside the conductor — about 200 lines of presence state smeared through ExerciseBase. We pulled it into its own PresenceGate file. Nothing about the behaviour changed; it just moved somewhere you can read and unit-test it on its own. Here's the one-way flow of a single frame:

💡 Why the split is worth it

The confirm / grace / resume timers (confirm 500 ms* / grace 900 ms / resume 320 ms) used to be untestable without booting a whole fake exercise and pumping frames. Alone in PresenceGate with an injected clock, they're plain unit tests — 17 of them, though 2 are currently red over a confirm-duration bug (see §06). The conductor's processPose also reads as a clean line now instead of 60 lines of interleaved presence bookkeeping. *Design/test value; the code constant currently ships 900 ms — §06.

01 The raw pixels · ios/Runner/SegmentationService.swift · android/…/SelfieSegmentationHelper.kt

Where the two numbers come from — native selfie segmentation

§00 hand-waved the very first arrow — "the camera counts person pixels." Here's what actually runs, and it's the one step that lives in native Swift + Kotlin, not Dart.

Everything else in this doc is Dart. But ML Kit's selfie segmenter and the raw camera mask live on the platform side, so the measurement does too. Its entire job: turn one camera frame into exactly two numbers — personRatio and softPersonRatio — and push them to Dart over an event channel. Raw masks and camera bytes never cross that channel; only the two ratios do. iOS and Android are line-for-line equivalents, so each idea below is shown on both.

🧒 Like you're five

The phone paints a stencil over the camera picture where every pixel gets a "how sure am I this is a person?" score from 0 to 1. Native just counts two things: what fraction of the stencil is confidently a person (strict), and what fraction is loosely a person (soft). Two percentages, handed over the wall. It never decides "someone's here" — that's Dart's job in §02.

⚠️ Watch out — the bypass is one-shot and self-clearing

bypassThrottleOnce flips true on requestSample() and back to false on the very next shouldProcess(). So a poke buys exactly one fresh frame, never a burst. Layer Dart's own 200 ms REQUEST_SAMPLE_COOLDOWN on top (§02) and even five triggers firing at once yield at most one forced sample per 200 ms. On iOS the flag is guarded by bypassLock because camera frames and the Flutter method call arrive on different threads; Kotlin leans on @Volatile for the same reason.

Two sieves over the same pile of sand. The fine sieve (strict, 0.82) only lets through pixels the phone is really sure are "person" → personRatio. The coarse sieve (soft, 0.35) lets through anything person-ish, even a backlit or blurry edge → softPersonRatio. A clear body fills both; a dim or half-in body fills mostly the coarse one. That's why Dart keeps both.

The defaults trap — native ships one set of numbers, Dart sends another

Look closely and you'll notice the native code has its own hardcoded thresholds — 0.92 strict, 0.55 soft, 140 ms interval. Those are only fallback defaults. On initialize(), Dart overrides all three from PersonDetectorConfig: 0.82 / 0.35 / 2000–8000 ms. The shipping app always runs the Dart numbers.

⚠️ Watch out — three sources of truth that aren't linked

The live thresholds live in PersonDetectorConfig (Dart). But if initialize() ever fails or is skipped, native silently falls back to 0.92 / 0.55 / 140 ms — a stricter person gate and a ~14× faster cadence than intended. Those defaults are duplicated across the Swift file and the Kotlin file, neither wired to the Dart config. Today Dart always initializes before start(), so it's fine — but that's three places to keep in sync by hand, and a good candidate for the recap list.

        now.difference(last) < PersonDetectorConfig.REQUEST_SAMPLE_COOLDOWN) {

  /// Fired once per native segmentation sample. Turns two raw mask ratios into
  /// a smoothed [presenceScore] and a debounced [personDetected] boolean.
  ///
  /// Two kinds of ratio arrive from native:
  /// - personRatio: fraction of frame pixels that are person at HIGH confidence.
  /// - softPersonRatio: same, but at a LOWER confidence threshold — catches a
  ///   noisy/backlit body the strict mask misses, so it's kept as a fallback.
  void _handleSegmentationEvent(Map<String, dynamic> event) {
    final personRatio = (event['personRatio'] as num?)?.toDouble();
    final softRatio = (event['softPersonRatio'] as num?)?.toDouble();
    if (personRatio == null || softRatio == null) {
      return;
    }

    lastPersonRatio = personRatio;
    lastSoftPersonRatio = softRatio;
    segmentationEventCount += 1;
    _lastSegmentationEventAt = DateTime.now();

    // Instantaneous (un-smoothed) evidence for THIS frame. Soft ratio is
    // discounted by SOFT_RATIO_SCORE_WEIGHT (0.45) so weak-confidence pixels
    // never count as strongly as high-confidence ones.
    final currentScore = math.max(
      lastPersonRatio,
      lastSoftPersonRatio * PersonDetectorConfig.SOFT_RATIO_SCORE_WEIGHT,
    );

    // EMA smoothing (alpha 0.30) damps single-frame mask noise. First sample has
    // no history, so seed the smoothed values with the raw ones.
    if (!_smoothedInitialized) {
      smoothedPersonRatio = lastPersonRatio;
      smoothedSoftPersonRatio = lastSoftPersonRatio;
      _smoothedInitialized = true;
    } else {
      smoothedPersonRatio = (smoothedPersonRatio *
              (1.0 - PersonDetectorConfig.RATIO_SMOOTHING_ALPHA)) +
          (lastPersonRatio * PersonDetectorConfig.RATIO_SMOOTHING_ALPHA);

      smoothedSoftPersonRatio = (smoothedSoftPersonRatio *
              (1.0 - PersonDetectorConfig.RATIO_SMOOTHING_ALPHA)) +
          (lastSoftPersonRatio * PersonDetectorConfig.RATIO_SMOOTHING_ALPHA);
    }

    // Smoothed evidence — the stable value UI/business logic reads.
    presenceScore = math.max(
      smoothedPersonRatio,
      smoothedSoftPersonRatio * PersonDetectorConfig.SOFT_RATIO_SCORE_WEIGHT,
    );

    // --- Detection decision: two instant escape hatches, then hysteresis. ---

    // (1) Instant-leave: near-empty frame. Trust the un-smoothed signal so we
    // drop immediately, and RESET the smoothed history to raw — otherwise a long
    // run of high presence would keep presenceScore "warm" for several frames
    // after the person is already gone.
    if (currentScore < PersonDetectorConfig.MIN_PERSON_RATIO_EXIT) {
      smoothedPersonRatio = lastPersonRatio;
      smoothedSoftPersonRatio = lastSoftPersonRatio;
      presenceScore = currentScore;
      personDetected = false;
      return;
    }

    // (2) Instant-enter: clearly a person this frame → detected, no waiting.
    if (currentScore >= PersonDetectorConfig.MIN_PERSON_RATIO) {
      personDetected = true;
      return;
    }

    // (3) Ambiguous middle (EXIT ≤ currentScore < ENTER): decide on the SMOOTHED
    // score with a two-threshold hysteresis band so the state can't flicker at
    // the boundary. Already in? hold until it falls below EXIT (0.02). Out?
    // don't flip until it clears the higher ENTER bar (0.03).
    if (personDetected) {
      personDetected =
          presenceScore >= PersonDetectorConfig.MIN_PERSON_RATIO_EXIT;
    } else {
      personDetected = presenceScore >= PersonDetectorConfig.MIN_PERSON_RATIO;
    }
  }

🧒 Like you're five

Two numbers come in: how much of the picture is definitely a person (hard), and how much is maybe a person (soft). We trust "maybe" less, so we shrink it to 45% before comparing. We keep a running average so one blurry frame doesn't lie. Then: almost nothing there? leave instantly. Clearly a body? enter instantly. Somewhere in between? fall back to the smoothed average and use the sticky ON/OFF dead-zone.

Why the three-way decision, in order

(1) Instant-leave · currentScore < 0.02
Near-empty frame. Trust the un-smoothed number so we drop this frame, and reset the smoothed history to raw so presenceScore doesn't stay "warm" for several frames after the person is gone.
(2) Instant-enter · currentScore ≥ 0.03
Clearly a body this frame → personDetected = true, no waiting.
(3) Ambiguous middle · 0.02 ≤ currentScore < 0.03
Decide on the smoothed score with the two-threshold band: if already in, hold until it falls below 0.02; if out, don't flip until it clears 0.03.

⚠️ Watch out — the "reset smoothed to raw" on instant-leave is load-bearing

Lines 264–266 look redundant next to personDetected = false, but they're not. Without snapping smoothedPersonRatio back down to the raw value, a long history of high presence would keep presenceScore elevated for several more frames after the person physically left — and the gate reads presenceScore for its own signals. This is the line that makes "leaving" feel instant. Don't delete it.

💡 Could be better

The blend weight (soft × 0.45), alpha (0.30), and both thresholds are the calibration heart of the detector, but the why behind each number lives only in the config doc-comments. A one-line "tuned on device DATE, N sessions" provenance note next to each would make future re-tuning far less scary.

    required DateTime now,
    required GatePhase phase,
    required Map<PoseLandmarkType, PoseLandmark> landmarks,
    Size? imageSize,
  }) {
    // Step 1: pose-returned trigger fires BEFORE any block/return.
    // When landmarks come back after a no-landmark run, immediately ask
    // segmentation for a fresh sample before the not-confirmed early-return
    // can block this path.
    if (_wasNoLandmarks) {
      unawaited(_detector.triggerCheck(reason: 'pose_returned'));
      _wasNoLandmarks = false;

    // Step 2: Sync presence state. Capture the was→now confirmed transition
    // to produce personLostNow without ExerciseBase needing a back-reference.
    final wasConfirmed = _personConfirmed;
    _syncPresence(now: now, phase: phase);

    final personLostNow =
        phase == GatePhase.seeking && wasConfirmed && !_personConfirmed;

    // Step 3: Block decisions.
    if (phase == GatePhase.seeking && !_personConfirmed) {
      final stableMs = _personSeenSince == null
          ? 0
          : now.difference(_personSeenSince!).inMilliseconds;
      return GateVerdict(
        proceed: false,
        block: GateBlock.searching,
        personLostNow: personLostNow,
        personStableMs: stableMs,
      );

      // Keep segmentation responsive while paused so re-confirmation is fast.
      unawaited(_detector.triggerCheck(reason: 'paused_pose_present'));
      return GateVerdict(
        proceed: false,
        block: GateBlock.paused,
        personLostNow: false,
        personStableMs: 0,
      );
    }

    // Step 4: Trouble triggers — run on every NON-BLOCKED frame (seeking-
    // confirmed, active-unpaused, done). Blocked frames intentionally skip
    // this section so the anomaly detector's window doesn't drift during a
    // pause and fire phantom triggers on resume.
    final avgPresence = _computeAvgPresence(landmarks);

    // Low-presence and edge-risk triggers: active phase only.
    final poseLowPresence = avgPresence < _AVG_LOW_PRESENCE_THRESHOLD;

      unawaited(_detector.triggerCheck(reason: 'pose_low_presence'));
    }
    _wasPoseLowPresence = poseLowPresence;

    final poseFrameEdgeRisk =
        _isPoseFrameEdgeRisk(landmarks, imageSize: imageSize);
    if (phase == GatePhase.active &&
        poseFrameEdgeRisk &&
        !_wasPoseFrameEdgeRisk) {
      unawaited(_detector.triggerCheck(reason: 'pose_frame_edge'));
    }
    _wasPoseFrameEdgeRisk = poseFrameEdgeRisk;

    // Anomaly trigger: any non-blocked phase (seeking-confirmed, active, done).
    _anomalyDetector.update(avgPresence);
    final nowAnomaly = _anomalyDetector.isAnomalyConfirmed;
    if (nowAnomaly && !_wasPoseAnomaly) {
      unawaited(_detector.triggerCheck(reason: 'pose_anomaly'));
    }
    _wasPoseAnomaly = nowAnomaly;

    return GateVerdict(
      proceed: true,
      block: null,
      personLostNow: personLostNow, // always false when proceed=true (see above)
      personStableMs: 0,
    );

Step 1 · pose-returned poke
If last frame had no skeleton and now one appeared, fire triggerCheck('pose_returned') before anything can block — get a fresh segmentation sample the instant the body reappears.
Step 2 · sync presence, capture the transition
Snapshot wasConfirmed, run _syncPresence, then compute personLostNow = "was confirmed, now isn't, and we're seeking." That flag is the only thing the base needs back to reset its hold-still timer.
Step 3 · block decisions
Seeking & not-confirmed → block searching. Active & paused → poke segmentation, block paused. Either way proceed=false and we stop here.
Step 4 · trouble triggers (non-blocked frames only)
Low-presence, frame-edge, and anomaly checks. Each fires its poke exactly once on a false→true transition.

⚠️ Watch out — why Step 4 is skipped on blocked frames

Blocked frames (seeking-unconfirmed, active-paused) return in Step 3 and never reach Step 4. That's deliberate: if the anomaly detector kept eating frames during a pause, its rolling window would drift, and the moment you resumed it would fire a phantom "anomaly!" poke. Skipping Step 4 while blocked freezes the window so resume is clean. The unit test active-paused frames do not feed the anomaly detector pins exactly this.

⚠️ Watch out — the trouble updates run wider than the trouble triggers

Read Step 4 carefully: the _wasPoseLowPresence / _wasPoseFrameEdgeRisk / anomaly booleans update on every non-blocked frame — including seeking-confirmed and done. Only the fires for low-presence and edge are gated to active; the anomaly poke fires in any non-blocked phase. If you "tidy" this by wrapping the whole block in if (active), you change when the edge-detectors are primed and you'll get spurious triggers on the first active frame. It reads odd; it's correct.

  void _syncPresence({required DateTime now, required GatePhase phase}) {
    final presentNow = _detector.personDetected;

    if (phase == GatePhase.seeking) {
      if (!_personConfirmed) {
        if (presentNow) {
          _personSeenSince ??= now; // record start of streak
          if (now.difference(_personSeenSince!) >= _PERSON_CONFIRM_DURATION) {
            _personConfirmed = true;
          }
        } else {
          _personSeenSince = null; // streak broken; reset
        }
      } else if (!presentNow) {
        // Person was confirmed but just left. Signal propagated via personLostNow
        // on the verdict; base clears _holdStillStartedAt.
        _personConfirmed = false;
        _personSeenSince = null;
      }
      return;
    }

    // done phase → no-op (same as original: exerciseState != activated returns).
    if (phase != GatePhase.active) return;

    if (presentNow) {
      _personLostSince = null;
      // A manual pause is only cleared by manualResume, not by presence.
      if (_isPaused && !_manualPause) {
        _resumePresenceSince ??= now;
        if (now.difference(_resumePresenceSince!) >=
            _PERSON_RESUME_CONFIRM_DURATION) {
          _isPaused = false;
          _resetTroubleDetectors();
        }
      } else {
        _resumePresenceSince = now;
      }
      return;
    }

    _resumePresenceSince = null;
    _personLostSince ??= now;
    if (!_isPaused &&
        now.difference(_personLostSince!) >= _PERSON_LOST_GRACE &&
        !_diagnosticMode) {
      _isPaused = true;
      _resetTroubleDetectors();
    }
  }

The anomaly detector — a self-calibrating tripwire

onPose Step 4 slipped one line past you: _anomalyDetector.update(avgPresence), and if it trips, a pose_anomaly poke asks segmentation to look now. 🧒 Like you're five

Instead of "alarm if the room drops below 50% bright," it says "alarm if the room suddenly gets a lot darker than it's been." It watches a slow average (the last ~2 seconds) and a fast one (the last ~0.3 seconds). When the fast one falls well below the slow one — the body was here and just faded — it trips. Because it compares against its own recent normal, a person who's always half-cropped never trips it; only a real change does.

Why not a fixed avgPresence < threshold? Because "normal" isn't fixed. A push-up close to the camera with cropped legs might sit at 0.6 forever; a full-body side-view at 0.9. A fixed floor either nags the first user or misses the second. So the detector self-calibrates: whatever the signal has been lately becomes the baseline, and only a drop relative to that baseline counts as trouble.

class Debouncer {
  int currentFrame = 0;
  int requiredFrames;
  bool isActive = false;

  Debouncer({this.requiredFrames = 5}); // Default to 5 frames

  bool update(bool condition) {
    if (condition) {
      currentFrame++;
      if (currentFrame >= requiredFrames) {
        isActive = true;
      }
    } else {
      currentFrame = 0;
      isActive = false;
    }
    return isActive;
  }

  /// Thresholds: ≥2 fully outside or ≥5 within the 4% margin.
  bool _isPoseFrameEdgeRisk(
    Map<PoseLandmarkType, PoseLandmark> landmarks, {
    required Size? imageSize,
  }) {
    if (imageSize == null || imageSize == Size.zero) return false;
    if (imageSize.width <= 0 || imageSize.height <= 0) return false;

    final marginX = imageSize.width * 0.04;
    final marginY = imageSize.height * 0.04;
    var visibleCount = 0;
    var edgeCount = 0;
    var outsideCount = 0;

    for (final landmark in landmarks.values) {
      if (landmark.presence < 0.25 && landmark.visibility < 0.25) {
        continue;
      }
      visibleCount += 1;

      final outside = landmark.x < 0 ||
          landmark.x > imageSize.width ||
          landmark.y < 0 ||
          landmark.y > imageSize.height;
      if (outside) {
        outsideCount += 1;
        continue;
      }

      if (landmark.x <= marginX ||
          landmark.x >= imageSize.width - marginX ||
          landmark.y <= marginY ||
          landmark.y >= imageSize.height - marginY) {
        edgeCount += 1;
      }
    }

    if (visibleCount < 8) return false;
    return outsideCount >= 2 || edgeCount >= 5;
  }

❌ Rejected (2026-07-06) — do NOT make _computeAvgPresence side-aware

This callout originally suggested weighting by visibility or averaging only camera-side joints, on the premise that occluded far-side joints "carry low presence" and drag the average down in side-view. That conflated the two confidence fields: the average uses presence = P(landmark exists), which stays 0.988+ for occluded side-view joints (canonical-numbers.md, empirical 05-06); visibility is the field that drops (0.34–0.95) and never enters this average.     Map<PoseLandmarkType, PoseLandmark> landmarks, {
    InputImage? inputImage,

    // One wall-clock read per frame. `now` drives the FPS delta below;
    // `frameTimestamp` is the canonical frame clock every downstream stage reads
    // (gate confirm/pause timers, hold-still countdown, scale EMA). Same instant
    // by design — never call DateTime.now() again mid-frame or the timers desync.
    final now = DateTime.now();

      final deltaMs = now.difference(_lastFrameTime!).inMilliseconds;
      if (deltaMs > 0) {
        // Smoothed FPS = exponential moving average (90% history, 10% newest) so
        // a single slow frame doesn't jerk the value. fpsRatio (currentFps / 30)
        // then time-scales motion thresholds — e.g. glute_bridge multiplies its
        // rep velocity by fpsRatio so fast and slow devices count reps alike.
        final frameFps = 1000.0 / deltaMs;

    // frame, should we auto-pause, when to poke segmentation." It returns a

      debugData['personStableMs'] = verdict.personStableMs;

    // seeking, the hold-still countdown (base-owned state) must reset too.
    if (verdict.personLostNow) _holdStillStartedAt = null;

    final safetyError = checkSafety(smoothedLandmarks);
    if (safetyError != null) {
      resultIssues.feedback["System"] = safetyError;
      return [repCount, resultIssues.feedback];

    // checkExerciseState, so isInStartPosition reads a fresh value on this frame

    _updateScaleFactor(smoothedLandmarks);
