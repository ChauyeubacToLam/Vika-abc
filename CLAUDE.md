This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Vika is a Vietnamese-language Flutter fitness app combining:
- **Real-time AI pose coaching** during exercise sessions (Google ML Kit pose detection + selfie segmentation)
- **Personalized weekly training plans** generated by a recommendation engine
- **Premium Ivory design system** — a warm-cream + warm-dark + reserved-yellow visual language inspired by Future / Caliber / Ladder, with italic display typography and editorial pacing

All user-facing strings are in Vietnamese.

## Commands

```bash
flutter pub get          # Install dependencies
flutter run              # Run on connected device/emulator
flutter test             # Run tests
flutter analyze          # Run Dart analyzer/linter
flutter clean            # Clear build cache (fixes most build issues)
```

## Architecture

The app has two largely independent halves that share auth + persistence:

1. **Main app shell** — 5-tab navigation around the Premium Ivory design system
2. **Real-time exercise capture** — full-screen camera + pose pipeline launched from any tab via `Navigator.pushNamed('/exercise', arguments: ExerciseDefinition)`

### App shell + tabs

`MainShell` (`lib/screens/main_shell.dart`) hosts an `IndexedStack` of 5 screens with a frosted-glass `IvoryBottomNav`:

| Index | Tab | Screen |
|---|---|---|
| 0 | Trang chủ | `DashboardHomeScreen` |
| 1 | Lộ trình | `PlanScreen` |
| 2 | Khám phá | `LibraryScreen` |
| 3 | Tiến bộ | `ProgressScreen` |
| 4 | Hồ sơ | `ProfileScreen` |

Each tab keeps its own scroll state via the IndexedStack. The bottom nav (`lib/widgets/ivory/bottom_nav.dart`) is a pill capsule with 5 equal tabs, active state = yellow halo behind icon + bold label.

### Premium Ivory design system

Two parallel theme registers (don't mix them):

- **Main app** — pull from `VikaColors.of(context)` in `lib/theme/app_colors.dart`. Auto light/dark via system. Tokens in `lib/theme/tokens/colors_light.dart` and `colors_dark.dart`. Plan-tab typography helpers in `lib/widgets/plan/plan_typography.dart` (`PlanH1`, `PlanEyebrow`, `PlanP`). Tabular figures via `VikaIvoryMain.tabularFigures`.
- **v5 onboarding** — self-contained `V5.*` namespace in `lib/screens/onboarding/v5/v5_theme.dart` + `v5_primitives.dart`. Do not import V5 into main-app screens or vice versa.

Legacy jade-green `VFTheme` still backs the exercise/auth screens. Don't extend it.

#### Stage hero pattern (Home / Plan / Library)

All three primary tabs open with a **full-bleed dark stage hero** at the top:
- Bleeds to screen's top edge via `MediaQuery.removePadding(removeTop: true)` to defeat MainShell's SafeArea
- Warm-dark gradient (`bgInverse → bgInverseHi`), 36pt rounded bottom corners curving into cream
- Atmospheric stack: warm yellow ambient glow (top-right) + amber glow (bottom-left) + deterministic film grain (`Random(seed)` — never time-based) + 2 sparkle particles
- Inverted `WordmarkHeader` at the top, sparkle eyebrow, italic display headline, embedded interactive controls (Home: session brief card; Plan: week scrubber; Library: filter chips)
- Status-aware halo CTA (yellow with two-layer shadow)
- Below: cream body with content-specific layouts

This shared shape is what makes the three tabs feel like one app. When adding a new primary tab, follow the same pattern.

#### Library is data-driven

`LibraryScreen` renders by iterating over `librarySections` (a `List<LibrarySection>` defined in `lib/data/library_mock.dart`). `LibrarySection` is a Dart 3 sealed class with subclasses `LibrarySectionFeatured`, `LibrarySectionRail`, `LibrarySectionList`, `LibrarySectionStatBand`, `LibrarySectionCatalog`. Each section declares `filterKinds` for visibility. Adding new content (a new series, new goal category, new section type) = appending to `librarySections`; the screen and widgets don't need to change. The switch in `_buildSection()` is exhaustive — adding a new sealed subclass forces a compile error until you handle it.

### Real-time pose pipeline (per frame)

Camera → ML Kit Pose Detection → One Euro Filter smoothing → Person detection (selfie segmentation) → Exercise state machine → Per-metric analysis → UI feedback

### Exercise system

`ExerciseBase` (`lib/exercise/exercise_base.dart`) is the abstract base for all exercises. Three-state machine: `notActivated` → `activated` → `completed`.

- **Activation**: User must hold still in the correct starting position for 3 seconds
- **Active tracking**: Each exercise composes multiple `Metric` objects that independently analyze form aspects (depth, alignment, tempo, etc.)
- **Completion**: Triggered when target rep count is reached

Each exercise lives in `lib/exercise/<name>/` with a `metrics/` subdirectory. Register new exercises in `ExerciseDefinition` (`lib/models/exercise_definition.dart`) with metadata + factory function. Looking up an exercise by id uses `lookupExerciseDefinition()` in `lib/models/exercise_lookup.dart`.

### Recommendation engine

`lib/services/recommendation/`:
- **`RecommendationService`** — main API. `ensurePlanForCurrentUser(trigger:)` returns a `PlanSnapshot`. Persists via Supabase.
- **`Plan` model** (`models/plan.dart`) — `Plan` → `WeekPlan` → `SessionPlan` → `SlotAssignment` → `VolumePrescription`. v4.3 structure: 2 phases × 3 weeks + 1 deload = 7 weeks.
- **`FitnessRetestService`** — pending re-test detection (after deload, before next plan generation).
- **`WeeklyCheckInService`** — soft weekly wellness check-in; `isDue(recommendationId, weekNumber)`.
- Engine internals: `recommendation_engine.dart`, `progression_rules.dart`, `progression_service.dart`, `scoring.dart`, `stochastic_sampler.dart`, `templates.dart`.

The Plan tab consumes `PlanSnapshot` via `_PlanWeekMapper.fromSnapshot()` which adapts the engine output to display models (`PlanWeek`/`PlanDay`/`PlanExercise` in `lib/data/plan_mock.dart`).

### Persistence + auth

- **Supabase** (`supabase_flutter`) — primary backend. Tables: `recommendations_log`, `executive_summary`, `pending_fitness_retests`, weekly check-ins. `AuthService` handles Google/Apple/Facebook sign-in.
- **SharedPreferences** — local persistence (onboarding completion flag, ephemeral state). `OnboardingPersistence` is the wrapper.

### Key utilities (`lib/utils/`)

- **PoseSmoother**: One Euro Filter for low-latency landmark smoothing
- **PersonDetector**: ML Kit selfie segmentation at ~7Hz; dual-threshold (0.92 strict, 0.35 coverage) with 650ms presence confirmation
- **FrameBuffer**: Stores per-frame snapshots during a rep for peak detection and angle tracking
- **ExerciseLogger**: Aggregates per-rep data into set-level summaries
- **StickyDebouncer/Debouncer**: Hysteresis for state transitions (orientation detection uses 5-frame hysteresis)
- **OrientationLock**: Force portrait when needed; restore on screen pop

### Interpreter layer

`lib/interpreter/` analyzes logged exercise data post-set to detect form issues and generate coaching recommendations. Currently implemented for squats (`SquatInterpreter`).

### Voice coaching

`SquatVoiceCoach` + `QueuedAssetVoicePlayer` for real-time TTS during squat sessions. Also a `ViettelTtsService` for cloud-generated Vietnamese voice lines. Audio assets in `assets/voice/`.

## Key Patterns

- **No external state management** — uses StatefulWidgets with local state and direct object mutation
- **Stage Hero pattern** — primary tabs open with a full-bleed dark canvas (see "Premium Ivory" above). Interactive controls embed in the hero; cause→effect happens in one glance.
- **Data-driven Library** — adding content categories = appending to `librarySections` data, not touching widget code
- **`MediaQuery.removePadding(removeTop: true)`** at the screen root to let dark heroes bleed past MainShell's SafeArea
- **`ResultIssues.feedback`** is cleared every frame (current-frame only); **`ResultIssues.instructions`** is keyed by phase and persists across frames
- **Camera facing auto-detection** via shoulder-width/torso-height ratio (FRONT: >0.57, SIDE: <0.35)
- **Scale factor** from shoulder-to-hip distance normalizes metrics across body sizes
- **Single `frameTimestamp`** set once per frame to avoid timing inconsistencies
- **Pure black/white forbidden on the Premium Ivory surfaces** — use `ink` (`#1F1812` warm-dark) instead of black, `bgRaised` (`#FBF7EE` warm cream) instead of white. Yellow `#FFB701` reserved for four uses only: stat / dot / underline / CTA.

## Conventions

- Constants: `UPPER_SNAKE_CASE` (analyzer ignores `constant_identifier_names`)
- Classes: `PascalCase`, variables/methods: `camelCase`
- Exercise directories may use spaces in names (e.g., `glute bridge/`)
- Uses `flutter_lints` for analysis rules
- Single font family across the app: **Be Vietnam Pro** (bundled, weights 400/500/700/800 + italics). No other fonts.
- TODOs that block real-data wiring use `// TODO(wiring):` so they're greppable
